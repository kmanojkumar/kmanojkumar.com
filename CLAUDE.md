# Instructions for Claude (and other AI agents)

Personal blog for K Manoj Kumar at `https://kmanojkumar.com`. Astro 6 +
Tailwind 4, deployed on Cloudflare Workers. **Public** GitHub repo at
`github.com/kmanojkumar/kmanojkumar.com`.

## Critical rules

- **Never write a new blog post without explicit user consent.** "Add a post
  about X" is consent. "Brainstorm topics" or "what could I write next" is not.
- **Never commit + push manually. Always use `/ship`.** Claude Code: type
  `/ship` (or "release" / "ship it" / "commit and push"). Codex / other
  agents: follow the "Release workflow" pipeline in `AGENTS.md`. Both run the
  same flow: diff → doc audit → version bump in `package.json` + `CHANGELOG.md`
  → user confirms version → wait for explicit "push" → commit → `git pull --rebase`
  → push → `gh release create`. Push to `main` auto-deploys to Cloudflare via
  GitHub Actions. **No `Co-Authored-By` trailers in commits.** Canonical
  workflow: `.claude/skills/ship/SKILL.md`.
- **Never modify `wrangler.jsonc` to add secrets.** The repo is public. All
  CF API tokens / account IDs live in GitHub Actions secrets only.
- **Cap font weights at `font-semibold` (600).** No `font-bold`,
  `font-extrabold`, `font-black`, or `fontWeight: 700+`. Site-wide rule.
- **Use design-system utility classes** (see "Design system" below). Don't
  copy-paste long Tailwind chains — promote them to `@utility` in `global.css`.

## Frontmatter shape (`src/content.config.ts` is canonical)

```yaml
---
author: K Manoj Kumar              # optional; defaults to site.author
pubDatetime: 2026-05-17T00:00:00Z  # ISO-8601, z.coerce.date accepts ISO strings
modDatetime:                       # optional; same format
title: "Title goes here"
slug: optional-explicit-slug       # optional; derived from filename otherwise
featured: false                    # one post can be true at a time
draft: false                       # excludes from build entirely
unlisted: false                    # renders /posts/<slug> but hidden from listings/feeds/search
topics: [devops, automation]       # always an array; default []
ogImage: "../../../assets/images/posts/foo-cover.jpeg"  # relative from .md file
heroImage:                         # optional; in-body hero (separate from ogImage)
description: "1-2 sentences (~150 chars) — feeds, OG, JSON-LD all use this"
canonicalURL:                      # optional; if cross-posted
source:                            # optional; e.g. "x.com/kmanojkumar/status/123"
AIDescription: false               # editorial transparency: true if AI-generated description
---
```

## Content authoring conventions

- **Math:** inline `$E = mc^2$`, block `$$\int … $$`. Rendered at build via
  `remark-math` + `rehype-katex`. KaTeX CSS is bundled — no client JS.
- **Diagrams:** triple-backtick `mermaid` fences. Rendered at build via
  `rehype-mermaid` (Playwright + chromium). Output is inline SVG — zero client
  JS. Locally: `pnpm exec playwright install chromium` is needed to preview a
  page with a mermaid block.
- **Code blocks:** Shiki with themes `github-light` / `github-dark-dimmed`.
  Transformer shortcuts:
  - File name: ```` ```ts title="src/foo.ts" ```` (or `// foo.ts` as first comment).
  - Diff markers: `// [!code ++]` and `// [!code --]`.
  - Highlights: `// [!code highlight]` and `// [!code word:term]`.
- **Embeds in MDX:** prefer `astro-embed` components.
  - `<Tweet id="…" />` — static HTML, no client JS.
  - `<YouTube id="…" />` — lazy iframe, no autoplay.
  - `<Vimeo id="…" />`, `<GitHubGist url="…" />` also available.
- **Images:** put under `src/assets/images/posts/` (Astro Image pipeline +
  responsive variants) or `public/` (raw asset). Avoid external `https://*`
  URLs — they break offline reading and lose lazy-loading.

## Design system (`src/styles/global.css` + `theme.css`)

Tokens in `theme.css`:
- `--background`, `--foreground`, `--accent`, `--accent-foreground`,
  `--muted`, `--muted-foreground`, `--border` (per-theme)
- `--underline-offset: 4px` (shared, theme-independent)

Utility classes in `global.css`:

| Utility | Use for |
| --- | --- |
| `app-link` | Body / inline links — permanent underline (`/25` base → `/55` hover) |
| `app-nav-link` | Header nav + Card titles — hover-only underline |
| `active-nav` | Active page indicator |
| `app-h1` | Page titles (`text-3xl sm:text-4xl font-semibold tracking-tight`) |
| `app-h2` | Section headings (`text-2xl font-medium tracking-tight tabular-nums`) |
| `app-hero` | Homepage hero h1 (`text-4xl sm:text-5xl font-semibold tracking-tight`) |
| `app-section-header` | Section wrapper: `mt-12 mb-4 border-b pb-2 first:mt-0` |
| `app-pill` | Small bordered chips (month label, status) |
| `app-btn` | Buttons — pager, share, copy-link |
| `app-meta` | Muted mono meta lines (dates, reading time, counts) |
| `max-w-app` / `app-layout` | Container width + page padding |

**When in doubt: don't duplicate Tailwind chains. Promote them to a new `@utility`.**

### Vertical rhythm

Every gap above a heading is **48px** (`pt-12` for page top, `mt-12` for
section headings). Don't introduce other values.

## Build / dev / preview

```bash
pnpm dev                # http://localhost:4321 (no Worker — no redirects/md negotiation/PWA)
pnpm build              # astro check → astro build → pagefind → cp cf/_headers dist/_headers
pnpm preview            # serve dist/ via astro
pnpm preview:wrangler   # serve via wrangler on :8787 — needed to test Worker logic
```

**Do NOT** run `pnpm dev` in an agent loop — it never exits.

## Markdown twins (LLM endpoints)

Every URL has a `.md` sibling:

- `/` ↔ `/index.md`
- `/about` ↔ `/about.md`
- `/posts` ↔ `/posts.md`
- `/posts/<slug>` ↔ `/posts/<slug>.md`

The Worker (`src/worker.ts`) also serves the markdown version when the request
includes `Accept: text/markdown`. If you add a new HTML route, add a matching
`.md.ts` endpoint.

`public/llms.txt` (per llmstxt.org spec) gives crawlers a curated overview.
Keep it in sync with current posts when you add a featured/recent post.

## Redirects (`src/worker.ts`)

- **Canonical hostname** — any non-`kmanojkumar.com` host → 301 to canonical.
- **Ghost-era root paths** (`/automate-devops-with-ai-agents` etc.) → `/posts/<slug>`
  (301). Map is hardcoded — keep in sync when slugs change.
- **`/blog/*` → `/posts/*`** (Ghost variants).
- **`/archives` → `/posts`** (`/archives` was merged into `/posts`).
- **`/tags/*` → `/topics/*`** (renamed Tags → Topics; old URLs preserved).

## Things that will surprise you

- **`unlisted: true` posts** — page renders at `/posts/<slug>` and the
  `.md` twin exists, but hidden from home/posts list/topic pages, RSS / Atom /
  JSON, AND Pagefind search index.
- **`getSortedPosts` vs `getRenderablePosts`** — `getSortedPosts` excludes
  drafts + scheduled + unlisted (for listings). `getRenderablePosts` includes
  unlisted (for `getStaticPaths`).
- **View Transitions are on** (`<ClientRouter />`). After navigation, re-init
  code must hook `astro:page-load` or `astro:after-swap` — NOT
  `DOMContentLoaded`.
- **`trailingSlash: "never"` + `build.format: "file"`** — Astro emits
  `/posts/<slug>.html` (not a directory). Astro emits 301 from `/foo/` to
  `/foo` in prod.
- **Per-post Satori OG only fires when a post has no `ogImage` frontmatter.**
  All 4 current posts have an explicit `ogImage` cover, so Satori per-post is
  unused. The site-wide `/og.png` (Satori) is always generated.
- **`article:tag` meta tag, `<category>` in RSS/Atom, `tags` field in JSON
  Feed** — these names are fixed by the OG / RSS / JSON Feed specs even
  though our domain term is "topics". Values come from `data.topics`.
- **Headings in markdown body** — Tailwind Typography defaults are
  overridden in `typography.css` to cap at `font-semibold`. Don't fight it.
